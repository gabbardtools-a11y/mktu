# ПОЧТОВЫЙ ПРОТОКОЛ СЕМЬИ — обмен документами Мастер ⇄ роботы

Версия 1.0 · 10.10.2026 · Автор: Мастер Ибро · Утверждено Бро
Кому: всем 10 роботам семьи (seismos, atoros, naytea, iznaki, mktu, rastix, strunino, aipat, ipvsem, iqin)
Статус: ДЕЙСТВУЕТ с момента получения этого письма

---

## 1. Зачем это нужно

Раньше каждая передача инструкции выглядела одинаково тяжело: шифропакет, пароль в чат,
скачивание, распаковка. Это оправдано для СЕКРЕТОВ, но избыточно для обычных документов —
инструкций, протоколов, заданий, отчётов. Теперь обычные документы живут прямо в твоём
репозитории, в ветке `_mail`: Мастер кладёт письмо — ты его читаешь в любую минуту без
запросов и паролей. Никаких скачиваний ради текста.

## 2. Три канала семьи — главное

| Канал | Что ходит | Пароль |
|---|---|---|
| Ветка `_mail` твоего репо | инструкции, протоколы, задания, отчёты | НЕ нужен |
| Ссылка вида `https://iznaki.ru/dl/<случайный путь>/<файл>.zip` | только AES-256 zip с секретами | НУЖЕН — от Бро в чате |
| Чат с Бро | пароли, решения, слова-триггеры | — |

ЖЕЛЕЗНОЕ ПРАВИЛО: в ветке `_mail` и вообще в репо НИКОГДА не бывает секретов — ни ключей,
ни токенов, ни паролей, ни PAT. (Урок Сеймоса: README с ключом внутри сожгло аудит доверия.)
Увидел в письме что-то секретное — это нарушение протокола: сообщи Бро немедленно.
Особая осторожность — в ПУБЛИЧНЫХ репо (seismos, mktu, rastix, iqin): там `_mail` видна всему
миру, поэтому содержимое писем там — только неконфиденциальное.

## 3. Как читать почту (роботу)

Ты уже умеешь ходить в своё репо (обёртка + твой deploy-ключ + remote на порт 443).
Почта читается той же дорогой:

    git fetch origin _mail
    git log FETCH_HEAD --oneline -10          # что приходило
    git show FETCH_HEAD --stat                # последнее письмо: какие файлы
    git show FETCH_HEAD:mail/ИМЯ-ФАЙЛА.md     # прочитать письмо
    git checkout FETCH_HEAD -- mail/ИМЯ.md    # забрать файл в рабочую копию (опционально)

Важные мелочи:
- `git fetch` НЕ меняет твою рабочую копию — только приносит FETCH_HEAD. Это нормально.
- Если ветки `_mail` нет — писем нет, работай по текущим канонам.
- Deploy-ключ не работает с GitHub API — только git-over-SSH. Канон чтения — git fetch.
- Свою ветку `_mail` НЕ мержить в main без прямого задания Мастера.

## 4. Как ответить (отчёт робота)

Отчёты кладёшь в ту же ветку `_mail`, в папку с твоим именем:

    # в клоне своего репо:
    git fetch origin _mail
    git checkout -b _mail origin/_mail        # если локальной ветки ещё нет
    mkdir -p mail/ot-<твоё-имя>
    # создать mail/ot-<твоё-имя>/2026-ММ-ДД-тема.md и написать отчёт
    git add mail/ot-<твоё-имя>
    git commit -m "mail(<твоё-имя>): <тема отчёта>"
    git push origin _mail

Формат отчёта: шапка (От/Кому/Дата/Статус: отчёт|вопрос|тревога) + суть в 3–10 строках.
Пуш в `_mail` НЕ вызывает деплой сайта (деплой триггерится только пушем в main) — это
проверено по всем 10 workflow семьи 10.10.2026.

## 5. Как Мастер кладёт письмо

Мастер пишет письмо через GitHub API (учётка gabbardtools-a11y): файл
`mail/2026-ММ-ДД-<тема>.md` одним коммитом в ветку `_mail` твоего репо. Родитель первого
письма — голова main на момент отправки, дальше письма накапливаются линейно.
Каждое письмо содержит шапку: Кому / От / Дата / Статус (инфо | задание | срочно).

## 6. Правила приёма задания

- Письмо со статусом «задание» и твоим именем в «Кому» требует подтверждения: отчёт в
  `mail/ot-<твоё-имя>/` с тем же номером задачи.
- Статус «срочно» — прочитать немедленно при следующей рабочей сессии.
- Статус «инфо» — просто прочитать и помнить.
- Ничего не понял в письме — спроси отчётом-вопросом, НЕ выдумывай.

## 7. Что НЕ меняется этим протоколом

- Секреты по-прежнему ТОЛЬКО в AES-256 zip (pyzipper, WZ_AES) по ссылке /dl/, пароль —
  от Бро в чате. Открытый base64 приватников запрещён (IM-шлюз санитизирует и путает).
- Приёмка пакета — по sha256 содержимого внутри пакета (sha самого zip недетерминирован).
- «Экран ≠ файл»: байты проверять программно, не глазами.
- Восстановление личности и доступа — ВОССТАНОВЛЕНИЕ-ЛИЧНОСТИ-РОБОТА.md (в Ките v2,
  выдаёт Мастер или Бро).

## 8. Первое задание (проверка связи)

Прочитав это письмо, положи в свою `_mail` короткий отчёт
`mail/ot-<твоё-имя>/2026-10-10-протокол-принят.md`:
кто ты (имя, репо), что прочитал, что непонятно. Это тест канала — Мастер прочитает все 10.
